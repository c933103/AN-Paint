## Execution and evidence

1. **Own disjoint locale/consumer cohorts.** Reconcile develop, review branches and pending writes before each cohort. Keep language work separate from active engineering; recheck affected consumers when engineering changes them. Publish meaningful whole-priority/coherent language-family batches with independent review and concise findings to the designated repository. No Work-side tasks or agents are started under this plan.
2. **Fill missing P0 first, then P1.** Begin with recovery/save/destructive-operation semantics and their actual consumer branches. Prioritize the two new recovery warnings across affected variants while the larger low-resource language queues proceed independently. Preserve distinctions such as retained versus verified-readable, Save versus Export, memory versus disk capacity, non-destructive crop versus output-size change, and conditional versus completed operations. Do not invent unsupported technical terms to meet a count.
3. **Review every existing translated entry, including P2/P3.** Group by locale and real feature/consumer, check meaning against the source and actual operation, terminology, grammar, orthography, placeholders/plurals, units, accessibility labels, licences and retained attribution. Independent review must address consequential meaning and real uncertainty, not merely agree with a first draft. Previously recorded evidence is usable only after checking the current value, source and consumer still match its scope. Changed or unsupported entries return to review. Native-speaker certification is not claimed where absent and is not an invented gate; unresolved material meaning errors remain blockers.
4. **Account for complete review without a wording mirror.** Use compact cohort findings and immutable source/review links in the existing [translation tracker](https://github.com/c933103/AN-Paint/pull/56). Generate current coverage from typed keys and cohort scopes to reveal omissions, overlaps and invalidated evidence. Keep detailed inventories/logs outside the application tree if bulky. Do not copy the catalogue into permanent approval fixtures or add tests that freeze accepted prose. Sampling may help target runtime checks, but must not be reported as review of all strings.
5. **Validate each cohort and the integration.** Run all offered-catalogue structural checks, the priority manifest, format/escaping/legal/script constraints and affected host tests. Review actual consumers and select runtime tests for distinct routing, state, glyph/layout, RTL/vertical-writing and accessibility risks. Check long warnings and labels on relevant screen sizes/font scales; inspect truncation and unreachable content rather than assume translated text fits. Structural/source checks are not fluency or device evidence.
6. **Integrate onto current develop through reviewable PRs.** Retain the complete tree and executable modes, use expected-parent non-force updates, and read back the exact remote result. Require the current exact-head Codex review and required CI, without redundant review requests when automatic review is active. A newer source/head invalidates tests or reviews outside their proven reusable scope. Resolve concurrent changes explicitly; do not overwrite them.

The latest published release checked is [AN Paint 0.0.40](https://github.com/c933103/AN-Paint/releases/tag/v0.0.40), with APK, corresponding-source ZIP, verification JSON and SHA256SUMS. Use the established **c933103/AN-Paint GitHub release/publisher destination**, not an additional store or distribution channel. Do not publish a release until all of the following are verified:

- The requested P0/P1 translation scope is complete, with substantive fallback/exclusions explicitly resolved rather than hidden in presence counts.
- Every translated string in the candidate, including P2/P3, has completed the scoped review process, and material findings are fixed or have a justified recorded disposition. Reconcile all cohort scopes against the current candidate, including newly introduced/changed resources.

Missing/skipped/unrun checks are not passes. Ordinary resource-only evidence reuse does not exempt release qualification.

Private upgrade signing remains outside GitHub; no key or private backup is published.
- The established publisher request, version's public signing patch and release notes refer to the qualified exact source/artifacts. After publication, read back the release tag, assets and verification record and report the actual outcome.
