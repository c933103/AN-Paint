# PR #1 review and release corrections

Reviewed merged commit `a7e3cb9e6b58fe7c4338a48de0cd3cf864ff0b24` from
[PR #1](https://github.com/c933103/AN-Paint/pull/1). The archive was checked against
all 778 Git blobs and the complete Git tree, including removed files.
The merged PR's [build, regression/lint and Android 35 run](https://github.com/c933103/AN-Paint/actions/runs/34791305273)
completed successfully. Comparing locale/key/value inventories confirmed that
all 4,867 pre-existing strings were preserved by the consolidation.

## Findings corrected

- Coverage omitted 29 starter catalogues and did not account for local/English
  variant catalogues consistently. Every offered option is now accounted for,
  including shared regional bases and name-only fallbacks.
- Starter Save translations were visible in File but absent from the unsaved
  prompt. The prompt now aliases the same translated resource.
- Ainu contained unsupported Japanese placeholders; the Tai collection contained
  Thai placeholders despite having a distinct collection code. Both options
  retain their actual selected locale and English fallback. Okinawan Cancel and
  Cantonese Latin Save were corrected with the sources in translations/README.md.
- The Mongolian name metadata included an English gloss. It now follows the same
  native-name + code pattern as other choices. Joined words wrap into adjacent
  vertical columns, with intrinsic row height and an untruncated horizontal code.
- Translation instructions told contributors to edit generated XML without
  preserving JSON source. They now explain the actual regeneration/import path.
- The first release build exposed strict-C11 compilation of Kvazaar's GNU inline
  assembly. Its target now explicitly uses GNU C11. Original native source and
  recorded provenance remain unchanged.

## Scope and verification

The one-catalogue consolidation and direct chosen-locale resource selection are
retained. Partial starter vocabulary is not advertised as complete or as having
received native-speaker certification. Version 0.0.28 adds real release-variant
checks and a publication workflow that verifies exact payload and existing signing
identity before publishing. Final build/run/artifact hashes are recorded separately
in the release evidence and HANDOFF.md; this source review is not itself a test pass.

The first universal release attempt passed regression/lint but failed to compile
libheif's C++ file streams on 32-bit API 21. AOM's CMake flag helper uses
`CACHE ... FORCE`, adding `_FILE_OFFSET_BITS=64` to shared release flags. Those
stdio aliases need API 24 on 32-bit Android. The libheif target now explicitly
undefines that inherited macro on 32-bit API levels below 24; its bounded in-memory
image import/export API remains unchanged. The targeted compile check covers both
armeabi-v7a and x86. The original native source trees remain unchanged.
